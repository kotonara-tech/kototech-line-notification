# 04. 工程表(スプレッドシート)の形

通知の元になる工程表の形式。**運用者が編集するのはこのシートだけ**で、通知の内容・タイミングはここで決まる。

アプリの読み取りは `backend/internal/infrastructure/sheets` に閉じている。形式を変える場合は、このドキュメントと同じ変更で更新する。

## 方針

- **1 行 = 1 プログラム**。工程表を、表計算としてそのまま書ける形にする
- **列はヘッダー名で探す**。列の順序は自由で、独自の列(メモなど)を足しても壊れない
- 日付と時刻は**別の列**にする(日付を毎行入れるだけで、複数日のイベントも同じシートで扱える)
- 運用者が触らない列は、アプリが書く 1 列(`通知済み`)だけにする

## シート

| 項目 | 内容 |
| --- | --- |
| シート名(タブ名) | `工程表`(アプリは環境変数 `SHEET_NAME` に対応するが、Terraform からは渡していないため、**タブ名は `工程表` から変えない**) |
| ヘッダー | **1 行目**。以降の行がプログラム |
| スプレッドシート | 環境(dev / prod)ごとに別のものを用意する(Q14) |

## 列

| 列名 | 必須 | 入力 | 例 | 説明 |
| --- | --- | --- | --- | --- |
| `日付` | 必須 | 日付 | `2026/11/14` | 開催日 |
| `開始時刻` | 必須 | 時刻 | `10:15` | プログラムの開始時刻。**この時刻の `NOTIFY_LEAD_MINUTES` 分前以内**になると通知する |
| `プログラム名` | 必須 | テキスト | `基調講演` | 通知の本文に入る |
| `通知済み` | 必須 | **自動入力** | `2026-11-14T10:05:03+09:00` | アプリが、通知した日時を書き込む。**手で編集しない**(下記) |
| `場所` | 任意 | テキスト | `メインホール` | あれば通知に入れる |
| `イベント名` | 任意 | テキスト | `ことならテック Meetup` | あれば通知の先頭に入れる(複数のイベントを同じ LINE から配信するときの識別用) |
| `通知する` | 任意 | チェックボックス | ☑ / ☐ | **チェックを外す(`FALSE`)と通知しない**。休憩・準備など。空欄は「通知する」 |
| `終了時刻` | 任意 | 時刻 | `11:00` | 運用者の参考用。アプリは読まない |
| (そのほか) | - | - | `メモ` | 上記以外の列は無視する。自由に足してよい |

- 必須のヘッダーが 1 つでもないと、スキャンは**失敗**する(終了コード 1。足りないヘッダー名がログに出る)
- ヘッダー名は、前後の空白と全角・半角の違いを無視して照合する

### 入力の形式

| 項目 | 受け付ける形式 |
| --- | --- |
| 日付 | 日付型のセル(推奨)、または `2026/11/14`、`2026-11-14`、`2026年11月14日` |
| 開始時刻 | 時刻型のセル(推奨)、または `10:15`、`10:15:00`、`3:15 PM` |
| 全角 | `２０２６／１１／１４`、`１０：１５` も読める |

- **日付型・時刻型のセルを推奨**する。セルの表示形式やスプレッドシートのロケールに左右されない(内部の数値で読む)
- 文字列で入力する場合も読めるが、上の形式に限る。**日付と時刻を 1 つのセルに書く形(`2026/11/14 10:15`)は読めない**
- 日付をまたぐプログラム(深夜 0 時台など)は、**開始する日の日付**を入れる(`2026/11/15` の `0:05` など)
- タイムゾーンは日本時間(Asia/Tokyo)で解釈する

## 通知済みの扱い

- アプリは、通知を送ったあと、その行の `通知済み` に日時(日本時間、RFC 3339)を書き込む。**空でない行は通知済みとして扱い、再び通知しない**(読めない値が入っていても、通知済みとして扱う)
- **再通知したいとき**は、`通知済み` を空にする
  - ただし LINE 側が、同じ通知の重複を一定時間(約 24 時間)は受け付けない場合がある。その間は、再通知しても配信されず、通知済みになるだけのことがある(仕様は公式で確認する)
- アプリは、`通知済み` を書き込む**直前に工程表を読み直し**、その時点の行を探して書く。通知している間に行を挿入・削除・並べ替えても、別のプログラムを通知済みにしない(読み直しから書き込みまでの数百ミリ秒の間の編集は、Sheets API の仕様上、防げない。**イベント当日は、通知の時間帯に行の並べ替えを避ける**)
- 運用者が誤って編集しないよう、`通知済み` 列は**範囲の保護**(編集者を限定、または警告のみ)をかけておくとよい。ただし、**実行用サービスアカウントには編集を許可する**こと

## 通知の動き

- Scheduler が 5 分ごとに起動し、`開始時刻` までの残りが **`NOTIFY_LEAD_MINUTES`(既定 10 分)以内**で、**まだ始まっていない**、**通知済みでない**、**通知するが有効**な行を通知する
- 起動は 5 分ごとなので、通知は開始の(`NOTIFY_LEAD_MINUTES` − 5)分前〜`NOTIFY_LEAD_MINUTES` 分前の間に届く(既定の 10 分なら 5〜10 分前。D35)
- `NOTIFY_LEAD_MINUTES` は **5 以上**にする。起動の間隔より短いと、通知の対象になる時間に起動が入らず、通知されないプログラムが出る
- すでに始まっているプログラムは通知しない(起動が遅れても、始まったあとに「まもなく開始」を送らない)
- 同じ時刻に複数のプログラムがあれば、それぞれ別の通知として送る
- 配信は LINE の **broadcast(全友だち)**

### 通知の例

`イベント名` と `場所` があるとき:

```
【ことならテック Meetup】
まもなく開始します
基調講演
開始時刻: 10:15
場所: メインホール
```

`イベント名` と `場所` がないとき:

```
まもなく開始します
基調講演
開始時刻: 10:15
```

- 文面は、`backend/internal/infrastructure/line/template/starting_soon.go` のテンプレートで作る(MVP はテキスト)。見た目の改善(Flex Message 化)は、`docs/mocks/` で設計してから、テンプレートを足す(D28、D32)

## 読めない行の扱い

| 状況 | 動き |
| --- | --- |
| 日付・開始時刻・プログラム名がすべて空 | 黙って飛ばす(区切り行・メモ行として使える) |
| 日付や開始時刻が読めない、プログラム名が空 | **その行だけ飛ばして**警告をログに出す(行番号つき)。他の行は通常どおり処理する |
| イベント名・日付・開始時刻・プログラム名・場所が完全に同じ行が複数ある | 最初の行だけを使い、残りは警告して飛ばす(イベント名だけが違う行は、別のプログラムとして両方読む) |
| 日付や開始時刻の欄に、日付・時刻として不正な**数値**が入っている(例: 開始時刻に `1030`、日付に `20261103`) | 0 時や遠い未来として黙って読まず、その行を警告して飛ばす |
| 見出しの重複(必須の列)、または `通知` `場所` `イベント` を含むが正しいヘッダー名と違う見出し | スキャンは続けるが、警告をログに出す(任意の列は、打ち間違えると**黙って無視される**ため。とくに `通知する` の打ち間違いは、止めたい行まで通知してしまう) |
| 必須のヘッダーがない / シートがない / 権限がない | スキャン全体が失敗する(終了コード 1) |

## 設定する手順(環境ごと)

1. スプレッドシートを作り、シート名を `工程表` にする
2. [04-timetable-sample.csv](04-timetable-sample.csv) を取り込む(ファイル → インポート → 「現在のシートを置換」)か、同じヘッダーを 1 行目に書く
3. `日付` 列を日付型、`開始時刻` 列を時刻型にする(書式 → 数字)。`通知する` 列は、挿入 → チェックボックス
4. スプレッドシートを**実行用サービスアカウント**(`line-notifier-scan-runtime@<プロジェクト ID>.iam.gserviceaccount.com`)に、**編集者**として共有する
5. スプレッドシートの ID(URL の `/d/` と `/edit` の間)を、GitHub の Environment variable `SPREADSHEET_ID` に設定し、デプロイ(Terraform の `apply`)する
6. 動作確認: dev で、開始の数分後になる行を 1 つ作り、`NOTIFY_LEAD_MINUTES` 以内にして、Job を手動実行する(`gcloud run jobs execute`)。LINE に届き、`通知済み` に日時が入ることを確認する

## 変更するときの注意

- ヘッダー名を変えると、その列は読まれなくなる。必須のヘッダーなら、スキャンが失敗する
- 列名・形式の定義は、`backend/internal/infrastructure/sheets/repository.go` の定数と、このドキュメントで揃える
